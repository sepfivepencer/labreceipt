# AI assistance disclosure

OpenAI Codex provided substantial assistance on 5 September 2026. It helped research public sources, shape the threat model, write the initial Python implementation, generate tests, and draft documentation.

The repository records that assistance so a contest team does not mistake generated code for evidence of its own work. A participant must read, test, modify, and explain the code; verify the competition's current AI-assistance rules; and record each team member's contribution before submission. This repository alone does not establish contest eligibility, originality, authorship, or compliance.

## Runtime AI use

The verifier, impact engine, and receipt writer do not call a model. The `propose` command can call a user-selected OpenAI-compatible endpoint after the user passes `--allow-network`. It produces a `candidate` contract. LabReceipt rejects that contract during verification until a person runs `confirm` with a reviewer label.

No real model endpoint or official competition system was used during the initial validation. The model adapter tests use in-memory HTTP doubles. No benchmark score, customer claim, or contest result in this repository was generated by AI.

## Human review checklist

- Read every rule and artifact path in the candidate contract.
- Check that acceptance criteria measure the requested outcome rather than superficial formatting.
- Confirm data rights, model rights, and the competition's current disclosure requirements.
- Run the offline tests and reproduce the demo on another machine.
- Replace the example reviewer label with a truthful project identifier; the label is not an authenticated signature.
